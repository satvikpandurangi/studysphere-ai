# Institution branding implementation — 22 October 2026

Added an admin-only institution settings route, local preview/save/reset, bounded uploaded raster logos, readable theme colors and support contacts. Members can explicitly choose authorized institution branding in the existing sidebar. Canonical school identity, curriculum, account policy and learning permissions remain unchanged.

The forward migration adds a private configuration table and authenticated list/save RPCs with school-admin checks, row locking, optimistic versions, validation and audit events. Typed school labels do not expose configuration. Approved guardians/learners and member staff can read; editors cannot save.

Local PostgreSQL tests cover previous-schema upgrade/preservation, member/guardian/typed-label boundaries, cross-school and role-only write denial, direct-table/anonymous denial, version conflicts/reset, color validation, logo/contact/type bounds and revoked/paused access. Four browser-helper tests check contrast defaults/invalid choices and in-memory logo reuse/removal with mocked transport. Existing enrollment/assessment suites remain separate regression coverage.

Final local verification: `npm run build`, `npm run lint`, `npm run check:worker`, `npm test` (52 passed, three hosted cases skipped) and `npm run docs:check` passed. No Worker source changed. The existing Node `module.register()` deprecation warning is non-fatal.

Browser verification uses real components/styles with synthetic service responses under ignored `.local/branding-preview/`: desktop identity/color/contact editing, save/application, reset preview/save/version advance/contact clearing, learner selection and refreshed revocation fallback, plus 390px learner sidebar selection/contacts. Screenshots remain in that ignored directory. This is not live Supabase verification; logo file decoding/upload still needs browser acceptance with actual files. Hosted migrations/deployment and three credential-dependent staging tests remain unverified.

See the [branding guide](../architecture/branding.md) for configuration, contracts, limits and rollout. Institutional feature/material entitlements, student account controls, usage monitoring and pilot operations are not completed by this milestone.
