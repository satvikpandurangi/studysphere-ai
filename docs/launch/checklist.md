# Institutional pilot and future launch checklist

This is a tracked acceptance checklist, not a claim that these items are complete. The current priority is an [free first-school private workspace](../product/institutional-launch.md). Apply it to the specific education stages being delivered; unimplemented stages must not be advertised as available.

## Product readiness

- [ ] Confirm the single school, cohort, minimum workflows and actual approved curriculum coverage.
- [ ] Record the free partnership, zero-cash provider envelope, account/deployment ownership, support and acceptance evidence; no paid provisioning is authorized.
- [ ] Verify agreed branding/configuration and private access to the institution's material.
- [ ] Apply the branding forward migration in staging; verify member visibility, admin-only writes, logo/contact rendering, reset, stale saves and refreshed revocation on target devices.
- [ ] Verify existing guardian/independent account journeys and decide policies for the new stages.
- [ ] Implement Standard 11–12 / PUC or college journeys if included in this delivery, before listing them as available.
- [ ] Finish assessment lifecycle, account controls and other milestone-1 gaps.
- [ ] Run the [repeatable validation and evidence ledger](pilot-acceptance.md); retain pending hosted/manual gates until actual evidence exists.
- [ ] Agree institutional entitlements, seats, usage increases, payment administration and exit/handover responsibilities; public subscription checkout is deferred.

Core synthetic access and learning results are recorded in the [29 October rehearsal](../history/2026-10-29-authenticated-pilot.md). Checklist gates requiring full/device/operational acceptance remain open; do not treat the earlier two-school fixture as a second customer.

## Access and data

- [ ] Run and pass staging tenant tests; prove cross-student and cross-institution denials.
- [ ] Verify institutional enrollment proof and access revocation independently of typed institution names.
- [ ] Verify draft hiding, quiz-answer protection, private assets and server-only secrets.
- [ ] Stop legacy upload writers, review private provider/ledger inventory, resume uploads through the new protocol and prove concurrent capacity/replacement/cleanup failure behavior in staging.
- [ ] Test migration of existing users/progress to the expanded academic model.
- [ ] Complete tested export/deletion handling and account support.

## Experience and operations

- [ ] Test signup verification, invitations and password recovery through actual email delivery.
- [ ] Test complete learning flows on target mobile/desktop devices and keyboard/assistive usage.
- [ ] Assign support, content review, operational escalation and privacy-request ownership.
- [ ] Publish reviewed privacy/consent/institutional agreements and retention process for the launch audience.
- [ ] Rehearse backup/restore, deployment/rollback and provider failure handling.
- [ ] Prove core learning/progress flows work without AI; enable AI only with funded allowance and verified configuration, grounding, limits and fallback.
- [ ] Measure storage, egress, API and AI usage; approve the actual launch budget.
- [ ] Validate live frontend/API health and authenticated journeys after release.
- [ ] Record evidence, refresh docs and produce the verified source release.

## Deferred public release

- [ ] Reassess a sustainable budget and public support/content ownership before reopening public-launch work.
- [ ] Complete public learner onboarding without forced school affiliation.
- [ ] Define individual plans, billing and cancellation if subscriptions are selected.
